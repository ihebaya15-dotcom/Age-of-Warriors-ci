# Age of Warriors: No-Engine Mobile Battle Strategy

لعبة استراتيجية قتالية متكاملة وتجارية للأندرويد مستوحاة من ميكانيكيات "We Are Warriors!"، مبنية بالكامل بدون محركات ألعاب خارجية (No-Engine)، تعتمد على جسر عالي الأداء بين Kotlin الأصلي ومحرك ألعاب خفيف بلغة JavaScript النقي فوق HTML5 Canvas API بمعدل 60 إطاراً في الثانية.

---

### User Review & Critical Decisions

> [!IMPORTANT]
> تم تأكيد تفضيلات التصميم والآليات في المرحلة الأولى:
> - **النمط البصري**: رسومات كرتونية ثنائية الأبعاد ملونة وجذابة مع جزيئات المعارك (Battle Particles) وأرقام ضرر عائمة وشريط صحة ديناميكي.
> - **خريطة العصور**: العصر الحجري (Stone Age) ➔ العصر البرونزي (Bronze Age) ➔ العصر الحديدي (Iron Age) ➔ العصر الحديث (Modern War).
> - **نظام الصوت**: مُولّد مؤثرات صوتية إجرائي مدمج عبر Web Audio API (ضربات، رماية، إطلاق نار، دمار، نقود، نصر) بدون ملفات خارجية وبأعلى أداء وتزامن صوتي.

---

### 1. Overview & Core Concept

- **طبيعة اللعبة**: لعبة معارك ومسار خطي (1D Lane Strategy Battler) يتنافس فيها جيش اللاعب ضد جيش العدو انطلاقاً من قاعدتين متقابلتين.
- **حلقة اللعب الأساسية (Core Loop)**:
  1. جمع الغذاء (Food) تلقائياً بمعدل محدد كل ثانية.
  2. تجنيد وحدات المحاربين بتكلفة غذائية مناسبة للدفاع عن القاعدة ومهاجمة قاعدة العدو.
  3. كسب الذهب من قتل الأعداء والفوز بالمعارك.
  4. ترقية إنتاج الغذاء، سعة الغذاء، وقوة تحمل القاعدة، ثم جمع ما يكفي من الذهب للتطور إلى العصر التالي (Evolution).
  5. تصفير الذهب المؤقت عند التطور مع الحفاظ على الترقيات الدائمة وفتح وحدات وقواعد أحدث وأقوى بصرياً وقتالياً.
- **الهدف التجاري وميكانيكا التفاعل**: دمج نقاط إعلانات مكافأة (Rewarded Ads) عبر الـ Bridge الأصلي مع إمكانية مضاعفة الذهب بعد النصر، وشراء دفعة طعام طارئة أثناء الاشتباك، وتحدي الزنزانة (Dungeon / Boss Rush) للحصول على جواهر وترقيات دائمة.

### 2. User Experience & Visual Design

#### أ. تدفق تجربة المستخدم (User Flows)
1. **شاشة القتال الرئيسية (Battle HUD)**:
   - في الأعلى: رصيد الذهب الدائم، الجواهر، رقم العصر الحالي، ومؤشر سرعة اللعبة (1x / 1.5x / 2x)، وزر الصوت والإيقاف المؤقت.
   - في الوسط: ساحة القتال ثنائية الأبعاد (Canvas)، قاعدة اللاعب اليسارية، قاعدة العدو اليمينية، شريط صحة القواعد، والوحدات المتصادمة مع تأثيرات دماء وجزيئات ملونة وأرقام ضرر تقفز للأعلى.
   - في الأسفل: عداد الغذاء الحالي والسعة القصوى وشريط تعبئته التناظري، متبوعاً بأزرار نشر الوحدات الـ 3 الخاصة بالعصر النشط مع وقت التجهيز (Cooldown) وتكلفتها الغذائية.
2. **شاشة الترقيات والتطور (Upgrades & Evolution)**:
   - ترقية سرعة إنتاج الغذاء (Food Production Rate).
   - ترقية صحة القاعدة (Base HP).
   - زر التطور للعصر التالي عند جمع الذهب المطلوب مع شاشة احتفالية بتغيير مظهر القاعدة والوحدات.
3. **نمط الزنزانة (Dungeon / Boss Rush)**:
   - معركة خاصة ضد زعيم ضخم وموجات مكثفة لمضاعفة مكافآت الجواهر.
4. **تكامل إعلانات المكافأة التفاعلية**:
   - نافذة منبثقة أصلية أو محاكاة فيديو تجارية أنيقة بمؤقت 5 ثوانٍ تمنح الجوائز الفورية وتحدث حفظ البيانات.

#### ب. الهوية البصرية ونظام الألوان
- **الألوان الأساسية**:
  - خلفيات العصور: تدرجات سماء العصر الحجري (Amber/Sky)، العصر البرونزي (Sand/Warm Orange)، العصر الحديدي (Steel Blue/Crimson)، العصر الحديث (Asphalt/Emerald).
  - واجهة المستخدم: درجات داكنة أنيقة مع حدود ذهبية ساطعة، وأزرار تجنيد ثلاثية الأبعاد بظلال واضحة ورسوم توضيحية مميزة لكل وحدة.
- **الطباعة والحركة**:
  - خطوط واضحة عريضة، حركة كاميرا ديناميكية خفيفة عند حدوث انفجارات، واهتزازات لمسية (Haptic Vibration) عند نشر الجنود أو تدمير القواعد.

### 3. Key Product Decisions & Trade-Offs

1. **الرسم عبر HTML5 Canvas API داخل WebView المسرع عتادياً**:
   - *القرار*: استخدام Canvas 2D النقي بدون مكتبات ثقيلة، مدمج مع WebView في Jetpack Compose ومفعل به التسريع العتادي الكامل (`LAYER_TYPE_HARDWARE`).
   - *السبب*: سرعة إقلاع شبه لحظية، تحكم دقيق بكل بكسل، واستقلالية تامة عن محركات الألعاب الضخمة مع ضمان استهلاك بطارية وذاكرة منخفض جداً.
2. **حلقة اللعب ونظام الـ Delta Time**:
   - *القرار*: استخدام `requestAnimationFrame` مع حساب دقيق لفرق الزمن `dt = Math.min((now - lastTime) / 1000, 0.1)`.
   - *السبب*: الحفاظ على سرعة حركة وتحريك ثابتة عبر كل الشاشات والهواتف، ومنع قفزات الموقع الفيزيائية عند تبديل التطبيقات أو بطء مؤقت.
3. **نظام الذكاء الاصطناعي (FSM) وحركة المحور الأحادي**:
   - *القرار*: حالة لكل وحدة تنقلها تلقائياً بين `IDLE` ➔ `WALK` ➔ `ATTACK` ➔ `DIE` استناداً إلى مسافة أقرب هدف أمامي (وحدة عدوة أو قاعدة الخصم).
   - *السبب*: بساطة وكفاءة هائلة تسمح بعشرات الوحدات على الشاشة دفعة واحدة دون أي تراجع في الإطارات.
4. **التخزين الآمن عبر Android SharedPreferences**:
   - *القرار*: حفظ التقدم عبر كوتلن في `SharedPreferences` من خلال كائن JSON مشفر أو منظم، مع استرجاعه عند كل تشغيل وإتاحته لـ JS فوراً عبر الجسر `AndroidBridge`.
   - *السبب*: استقرار دائم حتى في حال حذف ذاكرة تخزين الـ WebView المؤقتة، ودعم كامل للعمل بدون اتصال إنترنت (Offline-First).

#### بنية الوحدات والبيانات لكل عصر (Ages Configuration)
1. **العصر الحجري (Stone Age)**:
   - مشاة خفيف: رجل العصا (Clubman) - سرعة عالية، مدى اشتباك قريب، تكلفة طعام منخفضة.
   - بعيد المدى: رامي الحجارة (Rock Thrower) - مدى 120px، ضرر خفيف، صحة منخفضة.
   - وحدة ثقيلة: راكب الديناصور (Dino Rider) - صحة عالية جداً، ضرر متوسط، سرعة بطيئة.
2. **العصر البرونزي (Bronze Age)**:
   - مشاة خفيف: حامل الرمح (Spearman).
   - بعيد المدى: رامي السهام (Archer).
   - وحدة ثقيلة: العربة الحربية (Chariot).
3. **العصر الحديدي (Iron Age)**:
   - مشاة خفيف: المبارز (Swordsman).
   - بعيد المدى: رامي القوس المستعرض (Crossbowman).
   - وحدة ثقيلة: الفارس المدرع (Armored Knight).
4. **العصر الحديث (Modern War)**:
   - مشاة خفيف: الجندي التكتيكي (Rifleman).
   - بعيد المدى: قاذف البازوكا (Rocket Launcher).
   - وحدة ثقيلة: دبابة القتال الرئيسية (Battle Tank).

#### واجهة التواصل (AndroidBridge Interface)
- `loadSavedData()`: ترجع بيانات اللاعب المحفوظة كـ JSON string.
- `saveGameData(json: String)`: تخزين التقدم بشكل فوري ودائم في SharedPreferences.
- `triggerRewardedAd(rewardType: String)`: فتح نافذة مشاهدة الإعلان ومكافأة اللاعب (2x Gold، Free Food، أو Dungeon Key).
- `performHaptic(pattern: String)`: تفعيل ردود الفعل اللمسية على الجهاز.

### خطة خطوات التنفيذ (Execution Steps)

1. **تكوين مشروع الأندرويد**:
   - إعداد اسم التطبيق ووصفه في `metadata.json` و `strings.xml`.
   - إضافة إذن الاهتزاز `VIBRATE` في `AndroidManifest.xml`.
2. **بناء الجسر الأصلي وواجهة WebView في كوتلن**:
   - إنشاء كلاس `GameStorage` للتعامل مع `SharedPreferences`.
   - إنشاء كلاس `AndroidBridge` مع دوال `@JavascriptInterface`.
   - بناء شاشة Compose تضم الـ WebView مع تسريع عتادي ودعم التدوير الكامل أو الوضع الأفقي/العمودي الملائم.
   - إنشاء واجهة تفاعلية للإعلانات بمكافأة (Native Rewarded Ad Dialog / Video Simulation) تمنح المكافآت الحقيقية.
3. **تطوير محرك اللعبة في الأصول (assets/index.html & game.js)**:
   - حلقة اللعب (Game Loop) ومصفوفات العصور والوحدات.
   - نظام FSM وإدارة حركة واشتباك الجنود.
   - نظام إطلاق المقذوفات والجزيئات وظهور أرقام الضرر.
   - نظام توليد الصوت الإجرائي Web Audio API.
   - واجهة المستخدم والتحكم باللعبة (UI Buttons, Cooldowns, Upgrades Modal, Dungeon Mode).
4. **التحقق والاختبار البرمجي**:
   - تشغيل `compile_applet` للتأكد من خلو المشروع من أي أخطاء تجميع وتوافقه الكامل.
